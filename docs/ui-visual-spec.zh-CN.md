# WhisperMac UI 视觉与状态设计规格

## 1. 用途、范围和交付边界

本规格将 [UI 改进执行计划](ui-improvement-plan.zh-CN.md) 的 P0 视觉决策固定下来，供设计、实现和评审使用。它覆盖 macOS 14+ 上最小 **980×720 pt** 的主窗口、空白/准备、运行中、完成后三种主状态，以及失败和运行时准备的分支。

配套原型为 `docs/design/whispermac-ui-prototype.html`。原型用于检查信息层级、尺寸、文案密度与状态切换；它是 **HTML 设计参考，不是 SwiftUI 实际截图，也不代表已经实现或验证的功能**。实现以源码能力和执行计划的真实性约束为准。

完整的[设计图、原型入口与实际检查记录](design/README.md)已单独整理。先看三态设计图，再阅读以下尺寸和交互约束。

这不是重做品牌或引入网页视觉语言的任务。应用应保持原生、安静、专业，像一台可预期的本地工具：文件队列易扫读，当前任务一眼可知，低频诊断在需要时才出现。

## 2. 设计目标和不可违反的事实

### 2.1 设计目标

1. 用户在打开窗口后的三秒内能知道下一步是添加媒体、下载模型还是开始转写。
2. 运行时能看清“正在预处理”还是“正在转写这个批次”，可以停止，且不会被不可靠的逐文件数据误导。
3. 完成后立刻看到真实产物和下一步入口；有 SRT 才给字幕预览，其他格式不会出现空预览。
4. 设置、日志和历史保持可达，但不与一次任务争夺首屏。

### 2.2 真实数据边界

- 批处理先依序预处理各输入，之后由一次 `whisper-cli` 调用转写整个批次。转写阶段没有可靠的文件 ID，禁止显示“正在转写第 2/3 个文件”、逐项百分比、单项成功或片段归属。
- CLI 报告的批次进度只能写作“批次估算进度”；没有事件时用不确定式指示器，不根据时间编造进度或剩余时间。
- 成功由服务正常返回及实际输出 URL 确认。进度到 100% 不能替代成功状态。
- 内置结果预览现只支持 SRT。TXT、VTT、JSON 成功也必须显示真实输出文件，但不显示虚假的内容预览。
- GPU + ANE 缺 encoder 时可回退 GPU；这是可选能力的提醒，不能伪装为阻断错误。

## 3. 主窗口骨架

窗口使用三层稳定骨架：64 pt 标题工具栏、可伸缩的内容区和 80 pt 固定底栏。窗口内容不可作为一张从上至下的长配置表滚动；只有左侧队列、右侧主面板内的长内容各自滚动。

```text
980 pt minimum width
┌────────────────────────────────────────────────────────────────────────────┐
│  64  WhisperMac                         [＋ 添加] [历史] [设置…]        │
├───────────────────────┬────────────────────────────────────────────────────┤
│  236 pt               │  1 pt separator                                  │
│  任务队列             │  主工作区（可滚动）                              │
│  文件列表 / 轻量空提示│  准备：任务选项 + 就绪摘要                       │
│  移除、清空           │  运行：摘要折叠 + 实时文本                      │
│                       │  完成：文件选择 + 仅 SRT 的只读预览              │
├───────────────────────┴────────────────────────────────────────────────────┤
│  80  当前状态／进度／停止（运行时）                         [开始转写]    │
└────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 尺寸和留白

| 部位 | 规格 | 目的 |
| --- | --- | --- |
| 标题工具栏 | 高 64 pt；左右内边距 20 pt | 放窗口级动作，不承载冗长状态说明。 |
| 左队列 | 宽 236 pt；最小 220、最大 280 pt | 让文件名、数量和整理动作稳定可见。 |
| 内容区 | 顶部内边距 28 pt、左右内边距 32 pt；区块间 24 pt | 形成单一阅读列，避免卡片堆叠。 |
| 字段行 | 常规高 28–32 pt；行间 12 pt | 保留原生控件的舒适点击目标。 |
| 固定底栏 | 高 80 pt；水平内边距 20 pt | 动作和运行状态不随内容滚走。 |
| 细分隔 | 1 px 系统 separator | 只在工具栏、主分栏、底栏和列表行用；不为每个信息块加框。 |

以 8 pt 作为空间基准：8 用于标签与值、16 用于同组控件、24 用于内容区段。不要以阴影、圆角卡片和大色块替代留白或标题层级。

### 3.2 工具栏

- 左侧是应用名。右侧依次放“添加媒体”“历史”“设置…”，有文件后，数量留在队列标题或主区摘要，不做可点击徽章。
- 设置包含 CLI、模型、界面语言、运行时诊断和下载；帮助、README、GitHub 等文档入口置于设置 sheet 底部。无当前任务动作时不要塞入工具栏。
- “添加媒体”支持 `⌘O`；工具栏动作以 SF Symbol 加本地化标签表现，不能只有图标。
- 工具栏不显示大标题、彩色横幅或营销句；当前任务状态放到底栏。

### 3.3 左侧任务队列

队列是本次任务的唯一输入清单。顶部显示“任务队列”和数量。空时只显示轻量提示 `尚未添加媒体` 与辅助文字，不在左栏重复完整投放区；完整添加/拖放邀请放在右侧空白态。拖入窗口时可用系统 accent 的细边框和浅色背景标示右侧主区，不能整窗闪烁。

有项目时每行高度约 64 pt，结构为文件图标、文件名、父目录辅助文字和移除按钮。长文件名中间截断；鼠标悬停、选中或 VoiceOver 焦点时可得到完整路径。相同 basename 必须显示父目录，避免误删或误选。64 pt 密度优先服务少量文件的扫读；50 项以上的紧凑 48 pt 行是后续优化，仍须保留父目录辅助文字，不能退回 40 pt 单行。

底部的“移除”和“清空列表”是次级、明确文字动作。运行中队列及拖放均锁定；保留可读状态并在辅助说明写“本次任务已锁定”。不允许新的文件看似加入却不会出现在本次快照中。

## 4. 三个关键状态

状态切换只替换右侧主工作区和底栏中的状态内容；工具栏和队列的位置不跳动。状态标题、图标、颜色和可行动作共同表达含义，任何颜色都不是唯一信号。

### 4.1 空白/准备态

准备区分为两个明确画面：**空白态**处理“还没有任务”，**就绪态**处理“已有输入，可以配置或开始”。配置不完整是就绪态内的就绪状态分支，不能再用欢迎画面遮住用户已导入的队列。

#### 空白态：没有输入

左侧保持 236 pt 的任务队列，显示轻量空提示 `尚未添加媒体` 与辅助文字 `拖入媒体，或使用“添加媒体”`。右侧不展示一整张禁用的配置表，而是显示下面的任务入口：

```text
准备转写

                         [audio waveform / document icon，40 pt]
                            添加媒体以开始                 20 pt
                           [＋ 添加媒体]                   主按钮

任务默认设置
输出位置       跟随每个输入文件夹
输出格式       TXT、SRT
语言           自动检测                           [调整选项]
```

- 图标为约 40 pt 的 SF Symbol，使用 `secondaryLabelColor`；它不是插画或品牌装饰。
- `添加媒体` 是右侧首选路径，与工具栏添加动作相同；空态需要同时支持点击和拖放。
- “任务默认设置”只显示输出、格式、语言三行的摘要，供用户建立预期，但不把全部开关塞进空态。`调整选项` 打开完整准备表单；底栏“开始转写”仍因无输入禁用，原因写作 `先添加媒体`。
- 原型中的示例文件、状态切换、主题和语言控件只属于应用外的演示实验台；产品窗口工具栏不包含这些演示控制。

首次打开且模型缺失时，空态不应把“添加媒体”误导为当前阻断项：右侧说明 `需要模型才能转写`，将“下载默认模型…”作为主按钮；工具栏“添加媒体”仍可用但为次级入口。底栏“开始转写”禁用并明确写 `缺少模型`。若 CLI 缺失，优先显示 `选择 CLI…`，因为现有安装器不下载 CLI。下载中替换为资源名称、下载/校验/解压阶段和取消操作；encoder 缺失只提示 GPU 回退，不能阻断。

#### 就绪态：已有输入

用户添加至少一个输入后，右侧切换为完整任务选项，不再显示空态图标或欢迎语。

```text
右侧主工作区（有输入且可配置）

任务选项
输出位置   [跟随每个输入文件夹                              ▾]
            若选择了目录：/Users/me/Documents/…              [更改…]

输出格式   [✓ TXT] [✓ SRT]
            [  VTT] [  JSON]    至少选择一种输出格式

语言       [自动检测                                              ▾]
翻译       [ ] 输出为英语

运行环境   GPU + ANE（实际使用：GPU）             [查看设置…]

就绪状态
● 已准备好处理 3 个文件。输出将在开始时创建。
```

- 输出位置是第一项，因为它影响用户对结果所在地的预期。默认“跟随每个输入文件夹”必须完整写出；选择目录后显示可截断路径和“更改…”。
- 四种格式固定为两行、每行最多两个 Toggle；不把四个选择硬挤在单行。最后一个已选格式不可取消时，控件禁用并显示 `至少选择一种输出格式`；不能静默吞掉点击。
- “语言”和“翻译”同行的条件仅限内容空间足够；窄窗口和大字号时自动纵向展开。翻译文案必须明确为“输出为英语”。
- “运行环境”只给请求方式和已知有效模式的短摘要。缺模型时此处改为警告行：`需要模型才能开始`，附“下载默认模型…”与“选择已有模型…”。缺 encoder 时说明可回退 GPU，并给可选下载入口。
- 运行时下载是准备态的替换内容：显示当前资源名称与阶段（下载/校验/解压）。总量未知时用旋转指示器；当前资源大小已知时才用确定式条，标注为当前资源进度。
- 空队列时底栏“开始转写”禁用，紧邻按钮显示原因 `先添加媒体`。配置不完整时显示具体缺项，不能只给灰掉按钮。

### 4.2 运行态

运行态的右侧主区从“任务选项”切换为“任务摘要 + 实时文本”。选项不消失为未知数据：用默认折叠的“本次任务”DisclosureGroup 显示开始时已冻结的快照，包含文件数、输出位置、格式、语言、翻译和有效加速模式。

```text
右侧主工作区

本次任务  3 个文件 · TXT、SRT                         › / 可展开

实时文本
正在转写此批次。实时内容可能与最终字幕不同。
────────────────────────────────────────────────────────────────
00:00:02  欢迎收听今天的节目。
00:00:05  我们先讨论……
                         [跟随最新：开]
```

底栏在该态负责唯一的过程语言：

```text
预处理：正在预处理 2/3 · meeting.mp4       ━━━━━━━─────      [停止]
转写：正在转写此批次（3 个文件）            ━━━━━━━━━── 估算  [停止]
停止：正在停止…                              ◌                 [停止（禁用）]
```

- 预处理可以给 `2/3` 和文件名，因为回调提供索引。转写只能称“此批次”；若 CLI 有可信值，显示“估算”并以辅助标签区分，不显示预计结束时间。
- 日志不占主区。出现失败、下载故障或用户点“查看日志”时，打开诊断 sheet/检查器并保留任务状态。
- 实时文本为辅助观察，不是最终结果：最多保留当前服务能提供的片段，滚动时默认跟随最新；用户向上滚动或关闭“跟随最新”后停止自动滚动。无实时片段时显示阶段解释，不能留一大片无标签空白。
- “停止”是唯一破坏当前运行的动作，使用普通 destructive 语义，并先变为禁用的“正在停止…”。不要把它与“开始转写”并列成两个同等可点的主按钮。

### 4.3 完成态

正常返回后右侧主区首先显示终态摘要、文件选择器和所选内容。完成的含义必须由“成功”文字、成功图标和语义色共同表达；不要只把进度条填满。不要把六行以上产物与完整预览同时堆在同一阅读列。

```text
右侧主工作区（成功且有 SRT）

✓ 已完成 3 个文件                                      [全部输出…]
所选字幕
[meeting.srt · Documents/Meeting ▾]

字幕（SRT）预览  [meeting.srt ▾]
────────────────────────────────────────────────────────────────
00:00:00,000 → 00:00:02,100
欢迎收听今天的节目。
```

- 选择器只列出可预览的 SRT，名称附父目录；它决定下方只读字幕内容。选择器和预览共同占右侧主区，避免一个长产物清单把预览推到首屏外。
- “全部输出…”打开 sheet，列出完成报告中确认存在的每个实际 URL、格式和各自的“在 Finder 中显示”动作。存在多个输入目录时，不使用一个含糊的总目录冒充全部结果。
- 没有 SRT 时，选择器改为“所选输出”，可选择实际 TXT/VTT/JSON 文件；主区显示格式和路径说明 `此格式没有内置预览。`，不出现空框或伪内容。
- TXT/VTT/JSON 的产物都在“全部输出”sheet 中呈现，不能因无法预览而被隐藏。
- 运行结束后实时文本不再作为最终结果保留。若产品未来保留它，必须标为“实时草稿，非最终输出”。
- 成功后底栏主动作是“显示所选字幕”；没有 SRT 时为“显示所选输出”。次动作是“新建任务”，它进入准备态但不自动开始、不清空队列；用户可以继续调整选项或明确清空列表。状态行保留最近终态 `已完成 · 3 个文件`。

失败和已取消是独立终态，沿用完成态的稳定版面但不出现成功产物：失败显示“批次失败”、一句可行动摘要、`查看日志` 和 `重试`；已取消显示“已取消”、`重新开始` 和 `调整选项`。二者不创建成功历史，也不把可能残留的文件写作成功产物。

## 5. 视觉语言

### 5.1 字体、图标和文案密度

| 层级 | 字体规格 | 用途 |
| --- | --- | --- |
| 窗口/区段标题 | SF Pro Text semibold，22 pt | `任务选项`、`实时文本`、`实际输出`；每屏最多一个此级标题。 |
| 普通正文 | SF Pro Text regular，13 pt | 控件标签、队列文件名、状态正文。 |
| 字幕正文 | SF Pro Text regular，14 pt | SRT 的时间码和内容，保证长文本可读。 |
| 辅助正文 | SF Pro Text regular，12 pt；小型标识可用 11 pt | 路径、进度限定词、解释、父目录。 |
| 强调数字/状态 | SF Pro Text medium，13 pt | 文件数、格式摘要、关键状态。 |

使用系统文本样式实现以上层级，使动态文字和中文/日文回退字体工作。不要把标题拉到 28 pt 以上，也不使用 Display 字体、全大写标签或字距夸张的网页式标题。SF Symbols 使用与正文相配的 13–16 pt，且必须有文字或辅助功能名称。

文案应有动作和对象，例如“下载默认模型…”、“在 Finder 中显示”、“正在预处理 2/3”。避免把实现细节塞进首屏，如模型文件名、命令参数、下载 URL、内部阶段枚举；这些信息只进入设置或可复制日志。

### 5.2 颜色和表面

优先使用 macOS 语义色和材料，适配明暗模式；下列 token 是语义映射，不要求在深浅色中硬编码同一 hex。

| Token | macOS 建议 | 使用范围 | 不能用于 |
| --- | --- | --- | --- |
| `accent` | `controlAccentColor`，默认系统蓝 | 主按钮、键盘焦点、选中行、投放高亮 | 大面积背景或所有次级按钮。 |
| `textPrimary` | `labelColor` | 标题、文件名、主要状态 | 低对比水印。 |
| `textSecondary` | `secondaryLabelColor` | 路径、限定说明、时间码 | 关键错误的唯一表达。 |
| `separator` | `separatorColor` | 结构边界、列表行 | 每个字段的外框。 |
| `success` | `systemGreen` + “已完成”文字/对勾 | 终态图标和小状态点 | 整个完成面板背景。 |
| `warning` | `systemOrange` + 具体缺项文字 | 可修复配置、GPU 回退 | 唯一的禁用原因。 |
| `error` | `systemRed` + 错误摘要 | 失败图标、错误操作、停止的文字/图标 | 整个窗口或完成面板背景。 |

背景保持 `windowBackgroundColor` / `underPageBackgroundColor` 的系统层级；列表选中使用系统 selection。只使用细分隔和留白，不叠放阴影卡片。若需要突出下载、失败或完成，采用原生 `ContentUnavailableView`、`LabeledContent`、`DisclosureGroup`、`ProgressView` 和小型 inline status，避免警示条常驻或大面积彩色面板。

### 5.3 控件层级

- 每个状态只允许一个 prominent 主动作：准备态为“开始转写”或“下载默认模型…”，运行态没有蓝色 prominent 动作，只有普通 destructive 边框“停止”，完成态为“显示所选字幕”或“显示所选输出”。
- “新建任务 / 更改… / 显示 / 查看日志 / 重试 / 清空列表”使用 `.bordered`、链接式文字或上下文菜单，按破坏性和频率选择，不与主动作竞争。“停止”使用普通 `.bordered` 样式配 `error` token 的文字和图标，不能做成实心蓝色按钮。
- Toggle、Picker、路径选择都保留系统外观。固定标签列的宽度不超过 104 pt；大字号或 CJK 文案下改纵向标签布局，绝不截断标签或压缩开关。
- 键盘焦点环使用系统蓝色 focus ring，不额外绘制黑色或高亮外框。禁用态仍可看出控件含义，并以邻近文字说明禁用原因。

## 6. 交互细则

| 元素 | 默认行为 | 特殊状态与反馈 |
| --- | --- | --- |
| 添加媒体 / 拖放 | 打开现有文件选择器或从右侧空态去重加入队列 | 支持、重复、不支持的数量均反馈；全部拒绝不能显示成功。运行中禁用。 |
| 队列行 | 点击选中，删除仅移除该文件 | 同名项显示父目录；完整路径可复制/VoiceOver 读取。 |
| 输出位置 | 默认跟随各输入目录，可选择共享目录 | 使用实际完成 URL 驱动“显示”；不能承诺单个总目录。 |
| 输出格式 | 至少选一项 | 最后一项不可取消时解释原因。 |
| 运行环境 | 显示请求与有效模式摘要 | GPU + ANE 缺 encoder 显示 GPU 回退和可选下载。 |
| 下载 | 用户明确点击才开始 | 资源级进度、阶段、取消、失败重试；不把局部百分比当总进度。 |
| 实时文本 | 默认跟随最新 | 用户滚动阅读后暂停跟随，可手动恢复。 |
| 完成产物 | 主区选择 SRT 或实际输出；“全部输出…”sheet 展示完整实际 URL | 每项可在 Finder 中显示；不存在或未确认的文件不呈现。 |
| 日志 | 默认隐藏 | 失败自动打开；可复制、可清除，保留可读错误。 |
| 历史 | 从工具栏打开 | 只显示实际成功记录；清除需保留现有确认。 |

## 7. 适配与可访问性

### 7.1 窗口和文字扩展

- 980×720 是完整布局的最低工作尺寸。左栏保持 236 pt，右侧及内容区可独立滚动；工具栏和 80 pt 底栏永远可见。
- 工作区宽度（窗口内容宽减队列与分隔线）达到 1100 pt 进入"放宽"档位，低于 1060 pt 才退回（40 pt 滞回，避免拖拽抖动）：阅读列上限由 760 pt 扩至约 820 pt 并在工作区内居中，表单控件与进度条在预设区间内弹性伸缩；档位由布局几何派生，不写入应用状态。
- 在 980 pt 下不可把左栏继续挤窄来维持横向字段。格式必须先换两行，语言/翻译再纵向排列，路径行可换行或中间截断并提供完整值。
- 1440×900 及全屏属于"放宽"档位：阅读列约 820 pt 居中，两侧对称留白，不把单行控件拉满全窗，也不留单侧大片空白。
- 运行态实时文本视口占据剩余高度（下限 240 pt），窗口越高可见片段越多；空间不足（大字体 + 展开详情）时保留页面级滚动兜底，跟随开关仍可达。
- 支持 EN、简体中文、日文。所有长度敏感文字采用自然尺寸，不能以固定英文宽度裁切；CJK 字符和长路径均要在 980 pt 复查。
- 支持较大系统文字：原型以 1.2×为最低检查点，底栏从 80 pt 增至 96 pt；一行放不下时状态行与动作行纵向堆叠、底栏相应增高，标题、状态、按钮允许换行；绝不让开始或停止移出可见区域。

### 7.2 键盘、VoiceOver 和运动

- Tab 顺序：工具栏添加 → 队列/整理动作 → 右侧选项按视觉顺序 → 活动内容 → 底栏停止/开始。`Esc` 只关闭 sheet 或菜单，不取消任务。
- Return 只在“开始转写”已可用且焦点不在文本/选择控件时触发；Space 保持系统 Toggle 和按钮行为。
- 队列必须向 VoiceOver 报出文件名、父目录（同名时）、选中与锁定状态。进度报出阶段、批次数和“估算”限定词。错误、禁用开始原因和最后格式限制均有明确 accessibility label/hint。
- 深色和浅色都用系统颜色；选中、警告、成功、失败不可只靠色相区分。
- 仅用淡入淡出或系统进度动效表示变化。开启“减少动态效果”时停止自动滚动动画、无位移过渡；信息仍立即可读。

## 8. 实现映射与验收

| 设计块 | 推荐 SwiftUI 结构 | 验收证据 |
| --- | --- | --- |
| 三层窗口骨架 | 工具栏 + `HSplitView` / 固定容器 + `PersistentActionBar` | 980×720 截图中动作栏可见，内容不整体长滚动。 |
| 队列 | `TaskQueueView`、`List` 或可访问的滚动列表 | 空态、50 个文件、同名不同目录、运行锁定。 |
| 准备态选项 | `TaskOptionsView`、`LabeledContent` / 自适应栅格 | 四格式两行、缺 CLI/模型、GPU 回退、EN/ZH/JA。 |
| 运行态 | `RunSummaryView`、`LiveTranscriptView`、`ProgressView` | 预处理 i/N、批次转写、取消中、跟随最新。 |
| 完成态 | `RunResultView`、实际输出模型、SRT-only `TranscriptPreview` | 成功有/无 SRT、失败、取消、多个输出目录。 |
| 设置与诊断 | 设置 sheet、日志/历史 sheet 或检查器 | 低频项目不抢首屏；失败能一键到日志。 |

视觉验收目标是使用配套原型和实际 SwiftUI app 各检查一次：空队列、缺模型、下载、运行、成功（有 SRT 和无 SRT）、失败、取消；每种至少检查 EN/ZH/JA、浅色/深色、1.2×大文字、键盘焦点、VoiceOver 和“减少动态效果”。设计原型只验证布局假设，不能替代实际 app 的功能验证；实际检查记录另行交付，不由本规格声明完成。
